## 3. Что исправлено в коде

1. **Нечёткое сравнение (опечатки) — только для «незнакомых» слов.** Обычные русские слова («простой», «точка») больше не превращаются в органы. Было: «простой кисты яичника» → «простой» ≈ «простата» → киста яичника терялась **молча**. Настройка: `matching.fuzzy_only_unknown_words`.
2. **Словарь органов (`locations`) расширен до всех основных органов и структур** — около 30 групп с синонимами. Органы без своих находок служат «соседями»: правило «ЧТО + ГДЕ» выбирает правильный ближайший орган. Пример: «регионарные лимфатические узлы» в протоколе щитовидной железы больше не «узел щитовидной». Добавлять органы и синонимы в YAML безопасно.
3. **Аббревиатуры пишутся ЗАГЛАВНЫМИ** (ОБА, ЖП, ЧЛС) и совпадают только буква в букву. Было: «Узлы в **обеих** долях щитовидной железы» → «обеих» (начальная форма «оба») = артерия ОБА → узел щитовидной железы терялся.
4. **Опечатки с перестановкой букв** («пзуыря» → «пузыря») теперь ловятся.
5. **Строка-подраздел не обрывает раздел органа.** Было: «Фаллопиева труба: не визуализируется» внутри раздела яичника обрывала раздел, и «Параовариально… образование» теряло орган. Теперь раздел открывает только строка-заголовок.
6. **Контекстные слова и исключения.**
   - У находки можно задать `exclude_scope: sentence`: исключение действует на всё предложение, а не только между запятыми.
   - «Тромб» помечен `context_sensitive: true`, у него есть исключения (аорта, сердце…). Было: «аневризма аорты, пристеночные тромботические массы» → **экстренная** тревога «тромбоз вен ног».
   - «Грыжа» тоже помечена как контекстное слово.
7. **Исключения может добавлять администратор, без программиста** (подробно в п. 5).
8. **BI-RADS:**
   - распознаётся запись «BI-RADS справа 2, слева 2»;
   - одна категория на всё исследование («категория Birads 2» в заключении) применяется ко всем образованиям;
   - категория из предложения с ДРУГИМ образованием по-прежнему не переносится.
9. **Размер из описания.** «Полип ЖП» в заключении без размера, а в описании «образование 3,6 мм — полип»: размер берётся из описания с пометкой, и порог 10 мм проверяется.
10. **Поглощение дублей.** «Патология эндометрия (полип)» → показывается только «полип эндометрия» (`subsumed_by`).
11. **Окна отрицаний настраиваются отдельно.** `negation_before_window: 6`, `negation_after_window: 8`, оба только в своей части предложения. Было: «варикозная деформация… отсутствует» (6 слов) и «без явлений… варикозной деформации» — ложный варикоз.
12. **Внематочная беременность** — новая экстренная находка. Раньше уходила планово как «образование яичника».
13. **.docx.** Загрузка и папка inbox теперь читают .docx — выданные протоколы именно в нём. Было: inbox молча игнорировал .docx, загрузка падала с ошибкой.
14. **Второй контур (без переобучения):**
    - **Детектор пропусков** в v5 был выключен, в **v5.1 включён обратно** по решению команды (`miss_threshold: 0.9`), см. п. 1а.
    - **Верификатор** судит только типы, где в обучении было ≥ 5 настоящих примеров (`verifier_trusted_types`). Было: «Полип желчного пузыря 12 мм» → «вероятно ложное» (p = 0,01), потому что настоящих полипов ЖП ≥ 10 мм в обучении было 0.
    - Если правило само измерило признак и порог выполнен, модель с ним не спорит.

## 4. Склейка строк «Ключ:» + значение на следующей строке — ВЫКЛЮЧЕНА

- **Что это:** в формах 1С «Конкременты:» и «не определяются» стоят на разных строках. Склейка делает их одним предложением.
- **Замер:** на 146 реальных и интернет-протоколах — **0 изменений** в находках и отклонённых кандидатах. Лучше не стало, хуже тоже.
- **Решение:** по вашему указанию не используется (`join_colon_lines: false`). Код оставлен, включается одной строкой в `findings.yaml`. Стоит перепроверить на полной выгрузке МИС: такая разметка в реальных данных встречается (2 протокола из 89).

## 5. Новые функции для администратора

**Вкладка «Настройки» — автоотправка пациенту без проверки.** Режимы:
- выключена;
- все плановые маршруты;
- только если врач УЗИ сам рекомендовал этого специалиста;
- только выбранные специалисты.

Правила:
- **Экстренные находки никогда не уходят пациенту автоматически.**
- Галочка «находки с пометкой „проверить“ всё равно ждут админа» включена по умолчанию.
- Админ получает пуш о каждой автоотправке. Каждое изменение настройки пишется в журнал (кто, когда, было/стало).
- API: `GET/PUT /api/settings/auto_send`.

**Вкладка «Словарь» → «Исключения».**
- Можно добавить слово-исключение для любой находки или для всех сразу, на всё предложение или только между запятыми.
- Кнопка «＋ исключение» есть и прямо в карточке находки.
- Исключения действуют сразу. Хранятся в базе, а не в YAML: в Docker папка `config` монтируется только для чтения. Выключенное исключение остаётся в списке.
- В «Не сработало и почему» видно, какое исключение помешало находке.
- API: `GET/POST /api/exclusions`, `DELETE /api/exclusions/{id}`.

**Пуш пациенту — заглушка с телефоном.**
- В кабинете пациента есть телефон: экран блокировки с пушами и SMS.
- Кнопка «Включить уведомления браузера» показывает новые пуши системным уведомлением компьютера. Это Notification API браузера, внешние пуш-сервисы не используются.
- `routes.yaml` → `push_on_lock_screen: generic` прячет текст пуша на экране блокировки: остаётся «новое сообщение в личном кабинете».
- Настоящая отправка — через приложение или ЛК клиники по тому же контракту `notify.to_patient`.
